# Remote sponsor capabilities

Server-only injected adapters: `createRemoteTools`; lazy real clients: `createLiveRemoteTools` from `live.ts`. Nothing calls a sponsor at import or client construction. Every operation checks readiness, calls the parent approval callback with exact payload/resource, uses a 30-second cancellation budget, and returns sponsor attribution and unknown cost. Never use demo adapters with customer data.

Kernel creates a disposable headless browser, permits only the explicitly approved HTTPS hostname, extracts 12KB of page text and deletes the browser. Sprites runs Python CSV normalization/deduplication (500 rows / 64KB) in an explicitly provisioned dedicated guest, using `execFile("python3", ["-c", program])` explicit argv and no file persistence. Executor performs a real `execute`/`tools.search` research capability discovery in an explicit organization; it does not call mail/calendar or arbitrary discovered actions. After real discovery, the caller reviews an exact public read-only tool path and adds it to `executorResearchTools`; `executeResearchTool(path, args)` invokes only that selected path, never arbitrary program text. Every invocation still requires exact payload approval. No default research path is invented because available apps depend on the authenticated organization. Neon inserts only five selected event fields, 1–20 events, with SQL parameters. Call `prepareSnapshotSharing()` after exact database approval before the first share; this separately approved capability creates only the dedicated table. `schema.sql` is also available for explicit provisioning. Factory does not run DDL.

SDK cancellation may leave remote execution completing even after the local wait ends; receipts are only emitted for completed calls. Kernel cleanup is attempted with a separate 5-second budget. Sprites guests are pre-provisioned and never auto-created/deleted. Exact SDK versions were installed in an isolated temporary package and `index.ts` plus `live.ts` passed strict TypeScript compilation. Nine offline tests passed, including executing the Python normalization program locally on synthetic CSV. Live account permissions remain unverified until approved synthetic live smoke. Sprites 0.2.3 requires Node >=24; Node 22 is not a supported live runtime.

Credentials: KERNEL_API_KEY, SPRITES_TOKEN, EXECUTOR_API_KEY, EXECUTOR_MCP_URL, NEON_DATABASE_URL. Each sponsor is independently enabled; missing Neon credentials do not disable Kernel. Executor needs its exact Connections-page MCP URL and an explicitly selected organization. The factory accepts only official hosted URLs with a matching organization path or bare /mcp with the explicit organization header. Pass dedicated spriteName/databaseScope/executorOrganization plus allowedResearchHosts and approval callback. Keep credentials exclusively server-side. Exact Neon connection target must be checked by caller against databaseScope before construction.

Official references: https://www.kernel.sh/docs/introduction/create ; https://fly.io/sprites/ ; https://v2.executor.sh/docs/mcp ; https://v2.executor.sh/docs/api-keys ; https://neon.com/docs/serverless/serverless-driver . Researched 2026-10-04. Executor exposes skills/execute/resume, rather than every app tool as an MCP tool. PAT endpoint includes `/org/<organization>/mcp`.

Pinned npm SDKs verified 2026-10-04: @onkernel/sdk 0.119.0; @fly/sprites 0.2.3; @neondatabase/serverless 1.2.0; @modelcontextprotocol/sdk 1.32.0. Scope inputs beyond credentials are required to prevent accidental resource selection: dedicated pre-provisioned spriteName, verified databaseScope, executorOrganization, allowedResearchHosts, optional reviewed executorResearchTools, and the parent approval callback. No live DDL, sprite provisioning, token probing or paid call was performed. The Sprites regression invokes the real Python program via executable plus argv, matching the installed SDK execFile transport; shell execution is never used.
